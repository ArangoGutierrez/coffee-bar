coffee-bar

Your Mac stays awake while a coding agent is working, and sleeps the moment the agent is waiting on you.

Green holds the machine awake. Slate lets it sleep. An illustration of when the assertion is held — not a measurement.

What you see in the menu bar

The cup tells you the state at a glance. These are the real glyphs, and they are monochrome on purpose: macOS tints template images to match your menu bar, so they stay legible on any wallpaper and in either appearance.

idle No agent is working. Nothing is holding your Mac awake.
serving An agent is working. The wake assertion is held.
attention An agent is blocked on you. Answer it and the work resumes.

The behaviour

Long agent runs and Mac idle sleep do not get along. The usual fix is caffeinate, or a toggle you flip and forget — both of which keep the machine awake whether or not anything is happening.

coffee-bar binds the wake assertion to agent state instead of to a timer or a switch. While Claude Code is running a tool, the Mac stays up. The moment every agent is blocked on a human, the assertion is released and the machine is free to sleep — and it wakes into work when you answer.

What it actually does

  • Holds PreventUserIdleSystemSleep, bound to live agent session state.
  • Holds no display assertion by default. The screen still sleeps while the work continues. A Display control in the panel opts in when you do want the screen kept on.
  • Releases when every agent is blocked on input, not when a timer expires.
  • Shows how many sessions are working, and which ones are waiting on you.
  • Retires a session whose agent crashed, so a dead process cannot pin the machine awake for ever.
  • Three positions — Off, Auto, On. Off is an absolute veto and outranks everything.
  • A battery floor: at or below 20% on battery, it does not hold.
No root. No password prompt. No kernel flags. No App Store. No network egress — it listens on a unix socket in a directory only your account can read, and posts nothing anywhere.

Install

  1. Install it. Homebrew builds from source on your machine, so there is no Gatekeeper prompt and nothing to notarise.

    brew tap ArangoGutierrez/coffee-bar
brew install coffee-bar

  2. Link it into /Applications. The app lands in the Homebrew prefix, and the install prints the one command that does this.

  3. Wire the five Claude Code hooks. coffee-bar learns what your sessions are doing from these and from nothing else, and it never writes your settings file for you. Until you add them the app runs but no event reaches it. Add this to ~/.claude/settings.json:

    {
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "curl -sS --fail-with-body --max-time 5 --unix-socket \"$HOME/Library/Application Support/coffee-bar/ingest.sock\" -X POST --data-binary @- http://localhost/event"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "curl -sS --fail-with-body --max-time 5 --unix-socket \"$HOME/Library/Application Support/coffee-bar/ingest.sock\" -X POST --data-binary @- http://localhost/event"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "curl -sS --fail-with-body --max-time 5 --unix-socket \"$HOME/Library/Application Support/coffee-bar/ingest.sock\" -X POST --data-binary @- http://localhost/event"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "curl -sS --fail-with-body --max-time 5 --unix-socket \"$HOME/Library/Application Support/coffee-bar/ingest.sock\" -X POST --data-binary @- http://localhost/event"
          }
        ]
      }
    ],
    "PermissionDenied": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "curl -sS --fail-with-body --max-time 5 --unix-socket \"$HOME/Library/Application Support/coffee-bar/ingest.sock\" -X POST --data-binary @- http://localhost/event"
          }
        ]
      }
    ]
  }
}

    The command is the same for all five. Only PreToolUse and PostToolUse take a matcher. Restart Claude Code afterwards, then open the panel: it tells you whether the hooks are reaching the app. The quick start has the full walkthrough and the first-run check.

Privacy

coffee-bar reads hook events to learn whether an agent is working. It does not read your conversations. last_assistant_message and transcript_path never reach a stored property, a log line, or anything rendered on screen — that boundary is held by tests, not by intention.

What this version is not

v0.1 supports Claude Code, and only Claude Code. There are no Codex or Cursor hooks yet: those adapters and the coffeebar-hook shim are planned for v0.2. Token and usage accounting is a later milestone again and does not exist in this release — if that is what you want today, CodexBar already does it well.

Lid-closed operation needs a privileged helper and is deliberately out of scope for a release that asks for no elevated privilege.

Requirements

  • macOS 14 or later
  • Claude Code, with the five hooks above installed
