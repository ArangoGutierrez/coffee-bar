# v0.4.0 release candidate

Draft only. This version is not published.

## Changes

- Request Mac sleep at the battery floor in every mode, after a bounded attempt to restore Coffee Bar's lid hold. Release wake assertions when battery data is invalid or missing.
- Protect lid journals and socket ownership against concurrent processes and unsafe paths.
- Bound command and hook deadlines, retain at most 256 finished sessions, and reduce repeated parsing and advisory reads.
- Add Cursor turn events, a local activity bridge, and a timed manual hold. Apps without task events need the bridge or manual hold.
- Give a short stale-probe warning in the panel. Preferences uses signed-helper guidance where available and keeps the manual install route for other builds. (#146)
- Preserve and check the probe's stable signing identifier when the release app is signed again.
- Update the four GitHub Pages action pins. The app has no external Swift package dependencies.

## Library compatibility

CoffeeBarCore adds public cases to `AgentTool`, `CursorEventKind`,
`PowerSource`, and `HoldSuppression`. Library clients with exhaustive switches
must handle the new cases when they update.

`HookHealth.settingsPath(for:)` now returns `String?`, and
`HookHealthReader.defaultURL(for:)` now returns `URL?`. Clients must handle a
missing settings path for tools that use the local activity bridge.

`ServingModel.init`, both `ServingModel.staleHelperAdvisory` overloads, and
`WatchdogInputs.init` add defaulted parameters. Ordinary calls remain valid;
stored function references may need changes. Rebuild library clients.

## Release gates

- Final shared tests, clean build, code review, and distribution checks must pass.
- Real battery-floor acceptance must cover a registered helper, a closed lid, another app's wake assertion, and sleep/wake.
- Apple notarisation still returns HTTP 403 for a required Developer agreement after the user reported acceptance. The Apple account or agreement fault must be resolved before notarisation.

The audit evidence and its limits are in [the audit report](../audit-2026-11-04.md). Token Tap (#15) is outside this release.
