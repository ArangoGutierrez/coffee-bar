# v0.4.0 hardware acceptance

Status: **not run**. Unit tests do not prove that this Mac sleeps.
Use the signed candidate from this checkout. Do not use measurements from an
older installed process as candidate evidence. Complete this check before
publishing v0.4.0.

## Prepare

1. Save work that a sleep request can interrupt. Keep the charger available.
2. Quit the installed Coffee Bar from its menu. Open the candidate and check
   that About and Preferences show version 0.4.0.
3. Record the candidate SHA-256, macOS version, hardware, battery charge,
   battery floor, power source, helper status, and test time.
4. Record the executable path and PID with `ps -axo pid=,comm=`. Check that
   the path is inside the candidate bundle. Do not select a PID by a partial
   process-name match.
5. In Preferences > Power, register the signed helper and approve it in System
   Settings if required. Record the initial lid power setting with
   `pmset -g custom`. Keep it for comparison after each test.

## Battery and lid

The battery floor is inclusive. On battery, a charge at or below the selected
floor must release Coffee Bar assertions, attempt to restore its owned lid
setting, and request Mac sleep. A failed helper call has a bounded wait.

| Case | Action | Required evidence |
| --- | --- | --- |
| Auto, above floor | Start a bridge or supported native task. Arm lid mode and close the lid. | Work continues; the task and hold are visible before closure. |
| Auto, at floor | With the lid closed, let charge reach the selected floor. | Mac sleeps; wake records show the transition; the owned lid setting is restored. |
| Foreign assertion | Repeat with a separately identified application holding a wake assertion. Record `pmset -g assertions`. | Coffee Bar requests sleep despite the other assertion; record whether macOS completes it. |
| On and manual hold | Repeat the floor check for On and the timed manual hold. | Both modes obey the same floor; the manual timer is cancelled. |
| Off, no task | Select Off, end all tasks, and repeat the floor check. | The floor still requests Mac sleep without a Coffee Bar wake assertion. |
| Wake and recovery | Wake the Mac, reconnect power, and inspect Preferences and power settings. | No retained Coffee Bar lid override or unexpected assertion; valid Auto activity can resume. |

Use `pmset -g log` to locate the matching sleep and wake times. A menu label
alone is not evidence of system sleep. If the battery is above the maximum
selectable floor, wait for normal discharge; do not change the policy limits
for this test. Stop testing and reconnect power if sleep does not occur at
the floor. Preserve the logs and report the failure.

Missing battery data and helper failure paths are covered by automated tests.
Do not force sensor failures or change privileged journal files on this Mac.

## Helper warning (#146)

Check a signed build with an inactive registered helper and a stale legacy
probe, then check an unsigned/Homebrew build separately. The compact panel
must direct the user to Preferences > Power. Signed builds must give the Arm
and System Settings route. Unsigned builds must show their actual, quoted
manual install command. An active registered helper must suppress both stale
and unverifiable legacy-probe warnings. Do not remove a legacy probe to test
the warning.

## Footprint

Use the verified candidate PID for every sample. After startup settles, record
CPU, resident memory, thread count, and descriptor count for at least five
minutes while idle, then with a task active. Repeat after many task start/end
events and after the UI opens and closes. Record sample interval, duration,
event count, and workload so a later run can reproduce the comparison.

Count only unique numeric `lsof` descriptor records. A foreign process limit
or a shell limit is not the app limit. Call growth retained only after three
consecutive positive settled deltas. Short CPU samples and stable resident
memory do not prove the absence of leaks; record these limits with results.

## Result record

Record pass, fail, or not run for each case, with artifact hash, PID and
executable path, timestamps, resource samples, assertion output, original and
final power settings, and matching sleep/wake entries. Keep private logs local
and link only redacted evidence. A failed or unrun battery/lid case blocks the
release.
